API de Gestión de Drones

Aplicación académica de escritorio construida con Java 17, JavaFX, FXML, Maven y PostgreSQL. Permite crear, consultar, actualizar y eliminar drones agrícolas o de vigilancia y demostrar patrones de diseño.

Arquitectura

  • modelo: entidades y jerarquía de drones. Se mantiene sin modificaciones para los nuevos patrones.
  • servicios: Builder, Prototype, Factory Method, Singleton, Bridge, Decorator, Composite y Adapter.
  • dao: contrato CRUD genérico y persistencia JDBC.
  • controlador: interacción entre la vista y la lógica.
  • excepciones: errores controlados mostrados en JavaFX.

Prototype

Prototype se encuentra completamente en el paquete servicios mediante Prototipo. El servicio crea una nueva instancia del mismo subtipo del dron origen, copia profundamente piloto y sensores, no utiliza Cloneable y no requiere PrototypeRegistry ni registro previo.

Bridge y Decorator

Bridge utiliza ControlDron como abstracción y ModoControl como implementador abstracto con exactamente dos subclases: ControlManual y ControlAutonomo. El modo seleccionado se persiste en PostgreSQL mediante la columna modo_control. Decorator utiliza DescripcionDron como componente abstracto con exactamente dos subclases: DronDescripcionBase y BateriaAdicionalDecorator; la selección de batería adicional también se persiste sin modificar Dron.

Composite

Composite modela una jerarquía de sensores mediante ComponenteSensor, SensorCompuesto y SensorHoja. La aplicación construye la estructura Sensor General solicitada por la actividad y la muestra desde un botón de JavaFX. La misma jerarquía se registra en PostgreSQL mediante sensor_composite como evidencia persistida.

Adapter

Adapter transforma una instancia de Mision a JSON sin modificar la entidad. ExportadorMision define el contrato objetivo, MisionJsonAdapter realiza la adaptación y ArchivoJson escribe el archivo en la carpeta exports.
